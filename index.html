Demystifying JSON Flattening & Array Strategies

How flatJSON2csv transforms hierarchical trees into relational rectangles for SQL, BI, and ML pipelines — without compromising data integrity, schema consistency, or privacy.

account_tree

What Flattening Achieves

Modern web APIs and document databases return hierarchical trees, but relational engines (PostgreSQL, Snowflake, BigQuery), spreadsheets (Excel), and data frames (pandas) demand 2-dimensional rectangular tables.

  • Dot-Notation Paths: Unnests nested properties like customer.address.city into distinct, readable CSV column headers.
  • Zero Data Loss: Preserves parent identity and relational context across every flattened row.
  • BI & Warehouse Ready: Eliminates manual ETL scripts or fragile JSON path extractors in BI dashboards.
layers

Flattening Depth Trade-Offs

Controlling recursion depth balances tabular accessibility with column count sprawl.

none Keeps nested objects as raw JSON strings. Ideal when downstream pipelines already parse JSON.
depth:1 Unnests top-level attributes only; deeper structures remain JSON strings.
depth:2 Recommended Sweet Spot: Expands metadata and immediate payload models without over-widening tables.
full Recursively traverses all object hierarchies down to terminal scalar leaves.
data_array

Array Handling & Use Cases

Arrays cannot be converted into single scalar cells without a deliberate structural transformation.

JSON String Compact: Retains arrays as deterministic JSON text (e.g. ["a", "b"]). Zero row explosion. Safest for multi-array records.
Columns Wide Format: Generates indexed columns (tags_0, tags_1) up to the cap. Best for fixed tuples (GPS coordinates, top 3 items).
Join Delimiter Text: Merges primitive elements into a human-readable string (e.g. tag1; tag2). Best for categories, keywords, and Excel search.
Explode Relational Unnest: Duplicates parent fields for each array element, producing 1 row per item. Essential for SQL joins. Safeguarded against runaway cartesian products.
